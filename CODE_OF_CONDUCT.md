# ORVIKA Code of Conduct

## Our commitment

ORVIKA aims to provide a respectful, constructive environment for people
interested in personal cyber safety, privacy, security engineering, and
accessible technology. Participation in project spaces is expected to be
professional, considerate, and focused on the work.

## Expected behaviour

Participants are expected to:
- Be respectful, patient, and constructive.
- Discuss technical disagreements using evidence and good-faith reasoning.
- Welcome questions and differing levels of experience.
- Give actionable feedback without personal attacks.
- Respect privacy, confidentiality, intellectual property, and licensing.
- Keep discussions relevant and avoid disclosing sensitive information.
- Follow the project's contribution and security-reporting procedures.

## Unacceptable behaviour

The following behaviour is not acceptable:
- Harassment, threats, intimidation, discrimination, or personal attacks.
- Hate speech, sexualised harassment, or deliberate humiliation.
- Doxxing or publishing another person's private or identifying information.
- Spam, impersonation, malicious links, or deliberate disruption.
- Sharing credentials, private keys, personal data, or confidential material.
- Unauthorised access, testing, exploitation, or interference with systems.
- Knowingly submitting malicious code, malware, backdoors, or deceptive
  changes.
- Repeatedly ignoring maintainer instructions or community boundaries.

## Scope

This Code applies to interactions in ORVIKA GitHub issues, pull requests,
discussions, review comments, and other project spaces when a person is
representing or participating in the ORVIKA project.

## Reporting a concern

Report conduct concerns privately to the repository owner through
https://github.com/ErTapanJatakia. Please include relevant links, dates,
and a concise description. Avoid reposting private information or
sensitive evidence in public issues.

For security vulnerabilities, use the private reporting process in
[SECURITY.md](SECURITY.md), not the conduct-reporting route.

## Enforcement

The project maintainer is responsible for reviewing reports and deciding
appropriate action. Depending on severity and context, actions may include
a warning, removal of offending content, restrictions on participation,
or a temporary or permanent ban from project spaces.

The maintainer will handle reports as discreetly as reasonably possible.
Retaliation against anyone who raises a concern in good faith is
unacceptable.

## Good-faith participation

This Code is intended to protect a safe and productive project environment.
It does not guarantee acceptance of contributions, access to project
resources, or any licence to use ORVIKA. The repository's
[LICENSE](LICENSE) and [CONTRIBUTING.md](CONTRIBUTING.md) govern those
separate matters.
